# MCity - מדריך מושגים לצוות

מדריך קצר בשפה פשוטה. עודכן 2026-11-16 לפי המבנה שנבנה בפועל (ACF, בלי JetEngine). מיועד לשני המפתחים:
- **מפתח ה-FE:** בנה עד היום אתרי תדמית ודפי נחיתה. זה הפורטל הראשון שלו.
- **מפתח ה-Backend:** מגיע מעולם ה-React וה-SPA. זו הפעם הראשונה שלו עם וורדפרס.

---

## 1. מה אנחנו בונים, במשפט אחד

אתר חדשות מקומי שבו **אותו דף בנוי פעם אחת, ומתמלא בתוכן אחר לפי העיר**. למשל: דף של מודיעין ודף של חיפה נראים אותו דבר, אבל מציגים כתבות ועסקים אחרים.

---

## 2. ההבדל בין אתר תדמית לפורטל (בעיקר למפתח ה-FE)

**אתר תדמית:** כל דף נבנה ביד. הטקסט והתמונות כתובים בתוך הדף עצמו.

**פורטל:** הדף הוא **תבנית ריקה**, והתוכן יושב במקום אחר (במסד נתונים) ונשפך לתוך התבנית.

תחשוב על תבנית לעוגיות. התבנית היא הצורה, והבצק הוא התוכן. בונים תבנית אחת, ומקבלים אלף עוגיות.

מה זה אומר לך בפועל:
- אתה **לא כותב** "כתבה 1, כתבה 2, כתבה 3". אתה מעצב **כרטיס כתבה אחד**, ואומר לאתר "תחזור על זה 5 פעמים עם 5 כתבות".
- הטקסט בתצוגה הוא תמיד "חור" שהנתונים ממלאים. את החורים האלה מחברים לשדות (ראה בהמשך "Dynamic Tag").
- חשוב לעצב גם **מצבים חריגים**: מה רואים כשאין כתבות? כשהכותרת ארוכה מאוד? כשאין תמונה?

---

## 3. מילון וורדפרס למי שבא מ-React (בעיקר למפתח ה-Backend)

| בוורדפרס אומרים | מה זה | הדבר הכי קרוב ב-React / SPA |
|---|---|---|
| **Post** (פוסט) | פריט אחד, למשל כתבה | שורה בטבלה / אובייקט אחד ב-JSON |
| **CPT** (Custom Post Type) | סוג תוכן משלנו. אצלנו כמעט אין: יש רק `videos`. הכתבות הן פוסטים רגילים | טבלה / collection |
| **Meta field** (שדה) | פרט אחד על הפריט: טלפון, כתובת, קישור | עמודה / key באובייקט |
| **ACF** | תוסף שמאפשר להגדיר שדות **במסך הניהול** (אצלנו הגרסה החינמית) | כלי ליצירת סכמה עם ממשק |
| **Taxonomy** (טקסונומיה) | דרך לסווג פריטים, כמו קטגוריות | enum או tags מרובי ערכים |
| **Term** (מונח) | ערך אחד בתוך הסיווג, למשל "חיפה" | ערך אחד ברשימת ה-tags |
| **Slug** | החלק של השם שנכנס לכתובת, למשל `haifa` | ה-param בנתיב |
| **Query** (שאילתה) | "תביא לי את הפריטים שמתאימים לתנאי" | `.filter()` / קריאת API עם פרמטרים |
| **Loop Grid** | רכיב של Elementor Pro שמריץ שאילתה ומציג את התוצאות בכרטיסים | `items.map(item => <Card />)` |
| **Dynamic Tag** | "חור" בתבנית שמתמלא מערך של שדה | `{item.title}` בתוך JSX |
| **Theme Builder (Elementor)** | כלי שבו בונים תבנית לכל סוג דף | קומפוננטת Layout / page template |
| **Hook** (action / filter) | נקודת חיבור בקוד של וורדפרס, שאפשר לשנות דרכה התנהגות | event listener / middleware |
| **Rewrite** | חוקים שמתרגמים כתובת לשאילתה | ה-router (React Router / Next) |
| **REST API** (`/wp-json/...`) | הכתובת שבה אפשר לקרוא נתונים בצורת JSON | כמו API רגיל |

שלושה הבדלים שכדאי לדעת מראש:
1. **אין build ואין deploy רגיל.** התוכן והשדות יושבים במסד נתונים ומשתנים במסך הניהול. שינוי בשם שדה ב-ACF הוא כמו שינוי שם עמודה בטבלה חיה.
2. **הקוד והנתונים לא באותו מקום.** אפשר לשכפל את הקוד, אבל התוכן נשאר במסד הנתונים. לכן עובדים על העתק (אצלנו `mcityportal.ussl.co.il`) ולא על האתר של המעצב.
3. **הרבה דברים נעשים בהגדרות ולא בקוד.** לפני שכותבים קוד, בודקים אם ACF או Elementor כבר יודעים לעשות את זה. ומה שדורש לוגיקה, נכתב בתוסף שלנו.

## 4. איך דף עיר עובד, בדוגמה

הכתובת: `/haifa/`

1. הגולש נכנס לכתובת.
2. וורדפרס רואה ש"haifa" היא **קטגוריה** (עיר), ומעביר את זה לתבנית של העיר ב-Elementor.
3. כל **קטע** בדף (חדשות, צרכנות, מומחים...) מריץ שאילתה: "תביא כתבות בנושא הזה, מהעיר הזו".
4. הפריטים מוצגים בכרטיסים, בסדר שנקבע ידנית (`menu_order`).

### איך כתבה "יודעת" לאיזו עיר היא שייכת
כתבה שייכת לערים ולנושאים דרך **קטגוריות**:
- **עיר:** מונח אב בקטגוריות (`haifa`, `modiin` ועוד, 14 ערים).
- **נושא עירוני:** מונח ילד לכל עיר, בשם `{עיר}-{נושא}` (למשל `haifa-consumption`). יש 9 נושאים.
- **ארצי (כחול):** הקטגוריה `news` או קטגוריות הנושאים הכחולים (`cat-2`).

העורך לא בוחר קטגוריות ידנית. בעורך הכתבה יש תיבה (`mcity-tools`) שבה מסמנים ערים ונושאים, והיא כותבת את הקטגוריות בשבילו.

### דוגמה עם שלושה פריטים

| פריט | איך משויך | איפה יופיע |
|---|---|---|
| כתבה על אירוע בעיר | עיר `modiin` + נושא `events` | בדף מודיעין, ובכחול אם סומן גם ארצי |
| עורך דין שעובד בשני אזורים | מומחה (משתמש), `mcity_cities` = חולון וראשון, תחום = עורכי דין | בדף מומחים של שתי הערים |
| משקפי הלפרין (עסק ארצי) | ארצי | בדף הראשי |

הכלל: **דף ראשי (כחול) מציג תוכן ארצי. דף עיר (אדום) מציג את תוכן העיר.** באתר האדום מוצג גם תוכן ארצי נבחר (חדשות וקטגוריות כחולות).

### שתי כתובות לכל כתבה
כתבה בעיר נגישה בכתובת כחולה `/{slug}/` ובאדומה `/{עיר}/{slug}/`. הכתובת הרשמית (canonical) היא תמיד הכחולה.

### איך מסדרים את הכתבות
סדר הכתבות בדף נקבע ב-`menu_order`, בגרירה במסך הכתבות (תוסף Simple Custom Post Order). הוא **גלובלי**: אותו מיקום לכתבה בכל מקום שהיא מופיעה.

## 5. מי עושה מה

**המעצב / מפתח ה-FE:** מעצב את התבניות ב-Elementor ומחבר אותן לשדות ולשאילתות.
**מפתח ה-Backend (אנחנו):** מגדיר שדות ACF חדשים, כותב את הקוד בתוסף שלנו, וגם אחראי על **החיפוש הגלובלי** ו**הגירת התוכן**. כל זה על העותק שלנו.

### שלושה כללי זהב
1. **שמות השדות נלקחים רק מהחוזה** (`data-contract-draft.md`) ומקובץ ה-ACF. לא ממציאים שם בצד.
2. **לא משנים שדה קיים בלי הודעה.** שינוי שם שובר את החיבור של כל כרטיס שהשתמש בו. שדות חדשים מוסיפים בקבוצה נפרדת.
3. **כל החלטה חדשה נרשמת ביומן ההחלטות** (`02-decision-log.md`), גם הקטנות.

## 6. ארבע מילים שקל להתבלבל ביניהן

| מילה | מה זה | דוגמה |
|---|---|---|
| **עיר** | איפה גיאוגרפית (מונח אב בקטגוריות) | מודיעין, חיפה |
| **נושא / קטגוריה** | על מה הכתבה | מבט לצרכנות, חיים טוב יותר |
| **תחום מומחה** (`author_category`) | מה המומחה עושה | עורכי דין, פיננסים |
| **ארצי / מקומי** (כחול / אדום) | האם מופיע בכל הארץ או בעיר | משקפי הלפרין = ארצי |

## 7. טעויות נפוצות (כדאי לא לעשות)

- לערוך נתונים ישירות במסד הנתונים. עושים את זה דרך מסך הניהול.
- לעבוד על האתר של המעצב או על האתר החי. עובדים על העותק שלנו.
- ליצור עיר חדשה ביד. הקוד מכיר רשימה קבועה של ערים ומזהים של תבניות (ראה חוזה, סעיף 15). הוספת עיר דורשת קוד.
- לתייג כתבה ידנית בקטגוריות. משתמשים בתיבת השיוך, אחרת הכתבה תסומן "נעולה".
- לבנות כתובות ביד. הכתובות מגיעות מה-slug של הפריט.
- לשנות שם של שדה קיים בלי להודיע למעצב.
- להניח שהאתר של המעצב הוא מקור האמת לשמות. הוא קריאה בלבד, אבל מה שאימתנו מהקוד והאדמין מופיע בחוזה.
