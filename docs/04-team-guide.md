# MCity - מדריך מושגים לצוות

מדריך קצר בשפה פשוטה. מיועד לשני המפתחים:
- **מפתח ה-FE:** בנה עד היום אתרי תדמית ודפי נחיתה. זה הפורטל הראשון שלו.
- **מפתח ה-Backend:** מגיע מעולם ה-React וה-SPA. זו הפעם הראשונה שלו עם וורדפרס ו-JetEngine.

---

## 1. מה אנחנו בונים, במשפט אחד

אתר חדשות מקומי שבו **אותו דף בנוי פעם אחת, ומתמלא בתוכן אחר לפי האזור**. למשל: דף של מודיעין ודף של חיפה נראים אותו דבר, אבל מציגים כתבות ועסקים אחרים.

---

## 2. ההבדל בין אתר תדמית לפורטל (בעיקר למפתח ה-FE)

**אתר תדמית:** כל דף נבנה ביד. הטקסט והתמונות כתובים בתוך הדף עצמו.

**פורטל:** הדף הוא **תבנית ריקה**, והתוכן יושב במקום אחר (במסד נתונים) ונשפך לתוך התבנית.

תחשוב על תבנית לעוגיות. התבנית היא הצורה, והבצק הוא התוכן. בונים תבנית אחת, ומקבלים אלף עוגיות.

מה זה אומר לך בפועל:
- אתה **לא כותב** "כתבה 1, כתבה 2, כתבה 3". אתה מעצב **כרטיס כתבה אחד**, ואומר לאתר "תחזור על זה 5 פעמים עם 5 כתבות".
- הטקסט בתצוגה הוא תמיד "חור" שהנתונים ממלאים. את החורים האלה מחברים לשדות (ראה בהמשך "Dynamic Tag").
- חשוב לעצב גם **מצבים חריגים**: מה רואים כשאין כתבות? כשהכותרת ארוכה מאוד? כשאין תמונה?

---

## 3. מילון וורדפרס למי שבא מ-React (בעיקר למפתח ה-Backend)

| בוורדפרס אומרים | מה זה | הדבר הכי קרוב ב-React / SPA |
|---|---|---|
| **CPT** (Custom Post Type) | סוג תוכן, למשל `news` או `expert` | טבלה / collection במסד נתונים |
| **Post** (פוסט) | פריט אחד מהסוג הזה, למשל כתבה אחת | שורה בטבלה / אובייקט אחד ב-JSON |
| **Meta field** (שדה) | פרט אחד על הפריט: טלפון, כתובת, קישור | עמודה / key באובייקט |
| **Taxonomy** (טקסונומיה) | דרך לסווג פריטים, כמו קטגוריות או תגיות | enum או tags מרובי ערכים |
| **Term** (מונח) | ערך אחד בתוך הסיווג, למשל "מודיעין" | ערך אחד ברשימת ה-tags |
| **Slug** | החלק של השם שנכנס לכתובת, למשל `modiin` | ה-param בנתיב (`/c/:area`) |
| **Query** (שאילתה) | "תביא לי את הפריטים שמתאימים לתנאי" | `.filter()` / קריאת API עם פרמטרים |
| **Listing Grid** | רכיב של JetEngine שמריץ שאילתה ומציג את התוצאות בכרטיסים | `items.map(item => <Card />)` |
| **Dynamic Tag** | "חור" בתבנית שמתמלא מערך של שדה | `{item.title}` בתוך JSX |
| **Theme Builder (Elementor)** | כלי שבו בונים תבנית לכל סוג דף | קומפוננטת Layout / page template |
| **JetEngine** | תוסף שמאפשר להגדיר CPTs ושדות **במסך הניהול**, בלי לכתוב קוד | כמו כלי ליצירת סכמה עם ממשק |
| **Rewrite** | חוקים שמתרגמים כתובת לשאילתה | ה-router (React Router / Next) |
| **REST API** (`/wp-json/...`) | הכתובת שבה אפשר לקרוא נתונים בצורת JSON | כמו API רגיל |

שלושה הבדלים שכדאי לדעת מראש:
1. **אין build ואין deploy רגיל.** התוכן והשדות יושבים במסד נתונים ומשתנים במסך הניהול. שינוי בשם שדה ב-JetEngine הוא כמו שינוי שם עמודה בטבלה חיה.
2. **הקוד והנתונים לא באותו מקום.** אפשר לשכפל את הקוד, אבל התוכן נשאר במסד הנתונים. לכן חשוב לעבוד על סביבת בדיקה (staging) לפני שנוגעים באתר החי.
3. **הרבה דברים נעשים בהגדרות ולא בקוד.** לפני שכותבים קוד, בודקים אם JetEngine כבר יודע לעשות את זה.

## 4. איך דף אזור עובד, בדוגמה

הכתובת: `/c/modiin/`

1. הגולש נכנס לכתובת.
2. וורדפרס רואה ש"modiin" הוא אזור, ומעביר את זה לתבנית של דף אזור.
3. כל **קטע** בדף (חדשות, מומחים, עסקים...) מריץ שאילתה: "תביא 5 פריטים שמתאימים למודיעין".
4. הפריט הראשון מוצג גדול (המרכזי), ו-4 האחרים קטנים.

### שני שדות שקובעים איפה כל דבר מופיע

| שדה | השאלה שהוא עונה עליה | ערכים |
|---|---|---|
| `scope` | האם הפריט ארצי או מקומי? | `national` או `local` |
| `area` | באיזה אזור (או אזורים) הוא מופיע? | אחד או יותר מ-14 האזורים |

### דוגמה עם שלושה פריטים

| פריט | scope | area | איפה יופיע |
|---|---|---|---|
| כתבה על אירוע בעיר | `local` | `modiin` | רק בדף מודיעין |
| עורך דין שעובד בשני אזורים | `local` | `holon` + `rishon` | בדף חולון וגם בדף ראשון |
| משקפי הלפרין (עסק ארצי) | `national` | (ריק) | רק בדף הראשי |

הכלל: **דף ראשי מציג רק ארצי. דף אזור מציג רק מקומי של אותו אזור.** לא מערבבים.

### מה זה "פריט מרכזי"?
בכל פריט יש תיבת סימון `is_featured`. מי שמסומן עולה ראשון בקטע ומוצג גדול. אם כמה מסומנים, הכי חדש מנצח.

---

## 5. מי עושה מה

**מפתח ה-FE:** מעצב את התבניות ב-Elementor (דף ראשי, דף אזור, כרטיסים) ומחבר אותן לשדות.
**מפתח ה-Backend:** מגדיר את ה-CPTs, השדות והטקסונומיות ב-JetEngine, ובונה את השאילתות והכתובות.

### שלושה כללי זהב
1. **שמות השדות נלקחים רק מהחוזה** (`data-contract-draft.md`). לא ממציאים שם בצד.
2. **לא משנים שם של שדה בלי להודיע.** שינוי שם שובר את החיבור של כל כרטיס שהשתמש בו.
3. **כל החלטה חדשה נרשמת ביומן ההחלטות** (`02-decision-log.md`), גם הקטנות.

---

## 6. ארבע מילים שקל להתבלבל ביניהן

| מילה | מה זה | דוגמה |
|---|---|---|
| **אזור** (`area`) | איפה גיאוגרפית | מודיעין–שהם |
| **קטגוריה** (`category`) | על מה הכתבה | מבט לצרכנות, חיים טוב יותר |
| **תחום** (`index`) | מה המומחה עושה | עורכי דין, פיננסים |
| **ארצי / מקומי** (`scope`) | האם מופיע בכל הארץ או באזור | משקפי הלפרין = ארצי |

---

## 7. טעויות נפוצות (כדאי לא לעשות)

- לערוך נתונים ישירות במסד הנתונים. עושים את זה דרך מסך הניהול.
- לעבוד על האתר החי. קודם בודקים בסביבת בדיקה.
- ליצור אזור חדש ביד בתוך דף. אזורים נוצרים רק במסך הניהול, ומשם הם מופיעים בכל מקום.
- לשכוח לתייג פריט. פריט בלי `scope` ו-`area` לא יופיע במקום הנכון, או לא יופיע בכלל.
- לבנות כתובות ביד. הכתובות מגיעות מה-slug של הפריט.
- להניח שהאתר של המעצב הוא מקור האמת לשמות. הוא קריאה בלבד, והשמות בו הם ניחוש עד שנאמת אותם.
