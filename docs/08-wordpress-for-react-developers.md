# וורדפרס, ACF ו-Elementor למי שבא מ-React ו-TS

מדריך אוריינטציה, צעד אחר צעד. מיועד למפתח ה-data/backend שמכיר API, SQL/NoSQL ו-TypeScript, ואין לו ניסיון בוורדפרס.
עודכן 2026-11-16 לפי המבנה שנבנה בפועל (ACF חינמי, בלי JetEngine).

**איך לקרוא:** כל שלב בנוי על הקודם. בסוף יש תרגיל ליום הראשון.
**סימון:** ⚠️ = לא אומת. צריך לבדוק בגרסה האמיתית או מול המעצב.

---

## שלב 0. התמונה הגדולה

וורדפרס הוא **מונוליט שמרנדר HTML בשרת** (PHP) ומחובר למסד MySQL או MariaDB. אין בו SPA ואין build בצד לקוח. כל בקשה מייצרת HTML מחדש (או מגיעה ממטמון).

```
דפדפן
  │  GET /haifa/
  ▼
מטמון עמודים (SiteGround Speed Optimizer)  ── יש? מחזיר HTML מוכן
  │  אין
  ▼
PHP: ליבת וורדפרס
  ├─ טוען תוספים (plugins) ותבנית (theme: Hello Elementor Child)
  ├─ ממפה כתובת לשאילתה (rewrite)
  ├─ מריץ שאילתה על MySQL (WP_Query)
  └─ בוחר תבנית ומרנדר HTML
        (אצלנו: תבניות Elementor Pro, Loop Grid, שדות ACF)
```

**מקבילה בעולם שלך:** Next.js עם SSR, בתוספת CMS (כמו Strapi) ובתוספת מסך ניהול, הכל בחבילה אחת ובשפה אחת.

**הערה חשובה:** אפשר להשתמש בוורדפרס כ-headless (REST API ופרונט ב-React). **זה לא המודל אצלנו.** העיצוב נבנה ב-Elementor בתוך וורדפרס. לא לערבב בין השניים.

## שלב 1. מסד הנתונים

כל התוכן בוורדפרס יושב בקבוצה קטנה של טבלאות. מי שמכיר SQL יתפוס אותן מהר.

| טבלה | מה בה | מקבילה |
|---|---|---|
| `wp_posts` | **כל סוגי התוכן**: כתבות, עמודים, תמונות, תבניות Elementor. עמודה `post_type` מבדילה ביניהם | טבלה אחת גדולה עם discriminator |
| `wp_postmeta` | שדות מותאמים לכל פוסט: זוגות `meta_key` ו-`meta_value` | **EAV** (entity-attribute-value) |
| `wp_terms`, `wp_term_taxonomy`, `wp_term_relationships` | טקסונומיות: קטגוריות, ערים, מדורים, וקשרים לפוסטים **ולמשתמשים** | tags ו-many-to-many |
| `wp_termmeta` | שדות מותאמים למונח (למשל `mc_slug` של תחום מומחה) | |
| `wp_users`, `wp_usermeta` | משתמשים ושדות שלהם. **אצלנו כל המומחים** | |
| `wp_options` | הגדרות האתר (מפתח וערך) | config table |

**עמודות עיקריות ב-`wp_posts`:** `ID`, `post_title`, `post_content`, `post_excerpt`, `post_status`, `post_name` (ה-slug), `post_type`, `post_date`, `post_author`, `post_parent`, `menu_order`.

**שלושה דברים שחשוב להבין:**
1. **שדה מותאם הוא שורה ב-`wp_postmeta`, לא עמודה.** אין סכמה קשיחה. להוסיף שדה לא דורש migration. מצד שני, כל ערך הוא מחרוזת, ושאילתה על כמה שדות יוצרת joins.
2. אין foreign keys אמיתיים. קשר בין פוסטים הוא בדרך כלל ID שמור כערך.
3. **`wp_term_relationships` משותפת לפוסטים ולמשתמשים.** אותה עמודת `object_id` יכולה להצביע על פוסט או על משתמש, ולכן מזהה פוסט ומזהה משתמש שווים עלולים להתערבב בשאילתות מסוימות. נבדק בחוזה (סעיף 4, סיכון 5).

### איך זה נראה כ-TypeScript

כך נראית כתבה ומומחה אצלנו, עם הערה מאיפה כל חלק מגיע:

```ts
interface Article {
  // wp_posts
  id: number;                    // ID
  title: string;                 // post_title
  slug: string;                  // post_name
  status: 'draft' | 'pending' | 'future' | 'publish'; // post_status
  date: string;                  // post_date
  authorId: number;              // post_author  (מומחה או צוות)
  menuOrder: number;             // menu_order (סדר ידני, גלובלי)

  // wp_term_relationships (קטגוריות)
  categories: number[];          // ערים (5..18), נושאי עיר, news
  catTwo: number[];              // cat-2: נושאים כחולים
  sections: number[];            // section: מדורים

  // wp_postmeta (שדות מותאמים, חדשים: רק בקבוצה נפרדת)
  lead?: string;
}

interface Expert {               // משתמש בתפקיד author
  id: number;                    // wp_users.ID
  email: string;                 // user_email (שם נשלחות שאלות)
  profession: string;            // usermeta (ACF)
  phone: string;                 // usermeta (ACF, כיום number)
  mcity_cities: string[];        // usermeta, מערך מסודר של מזהי מונחים כמחרוזות
  mc_active: '0' | '1' | '';     // usermeta
  mc_subscription_end: string;   // usermeta, Ymd
  authorCategory: number[];      // term_relationships, taxonomy author_category
}
```

חוזה הנתונים שלנו הוא בעצם **ה-interfaces של הפרויקט**. המעצב מחבר תבניות לשמות האלה, כמו שקומפוננטה מחוברת ל-props.

## שלב 2. סוגי תוכן, סטטוסים ותפקידים

**Post type (סוג תוכן):** ערך בעמודה `post_type`. אצלנו: `post` (כתבה), `page` (עמוד), `attachment` (קובץ מדיה), `videos` (סרטונים, CPT יחיד שלנו), `elementor_library` (תבניות).
**CPT (Custom Post Type):** סוג תוכן שאנחנו מגדירים. אצלנו אין CPT למומחים או לכתבות.

**סטטוסים של פוסט (`post_status`):**

| סטטוס | משמעות | קשור לדרישות הלקוח |
|---|---|---|
| `draft` | טיוטה | כתב יוצר טיוטה |
| `pending` | ממתין לעורך | עורך מאשר |
| `future` | מתוזמן לפרסום | תזמון פרסום |
| `publish` | מפורסם | |
| `trash` | באשפה | |

**תפקידים (roles):** RBAC מובנה, כולל רשימת capabilities לכל תפקיד.

| תפקיד | מה הוא יכול | אצלנו |
|---|---|---|
| Contributor | יוצר טיוטה, **לא מפרסם** | כתבי צוות |
| Author | מפרסם את הפוסטים שלו | **הוחלף שם ל"מומחה"**. כל המומחים משתמשים בו |
| Editor | מפרסם ומנהל את כל התוכן | בפועל זהה ל-Administrator |
| Administrator | הכל, כולל הגדרות ותוספים | |

מומחה הוא משתמש בתפקיד Author. הוא מקבל מייל ועונה בלי להתחבר (ראה שלב 6 ו-13).

## שלב 3. טקסונומיות

טקסונומיה היא **דרך לסווג פוסטים**. כל ערך בתוכה הוא "מונח" (term).

- **היררכית** (כמו קטגוריות): למונח יש אב.
- **שטוחה** (כמו תגיות): בלי היררכיה.

אצלנו כולן היררכיות:

| טקסונומיה | מה בה | כתובת |
|---|---|---|
| `category` | **ערים** (מזהים 5 עד 18), נושא עירוני `{עיר}-{נושא}` לכל עיר, `news` (מזהה 20) | `/haifa/` |
| `cat-2` | נושאים כחולים: חיים טוב יותר, בילוי ופנאי, מבט לצרכנות וילדיהם | `/cat-2/...` |
| `section` | מדורים. אב ארצי `artzi`, ואבות עירוניים | `/madorim/` |
| `author_category` | תחומי מומחים. מוצמדת למשתמשים ולפוסטים | `/index/` |
| `video_place` | מיקום סרטונים (CPT `videos`) | |

**מקבילה:** שדה tags מרובה ערכים, עם טבלת קישור (many-to-many) ועם כתובת ארכיון אוטומטית לכל ערך. **הכתובת האוטומטית היא הסיבה שדף עיר הוא קטגוריה:** `/haifa/` נוצרת מעצמה.

## שלב 4. מחזור חיי בקשה: מכתובת ל-HTML

כך וורדפרס מגיע מכתובת ל-HTML. זה המקביל ל-router ול-layouts אצלך:

1. **Rewrite rules:** טבלת חוקים שממירה כתובת לפרמטרים של שאילתה. `/haifa/` הופך ל"ארכיון של קטגוריה `haifa`". המקביל: הגדרת routes. **אצלנו יש חוקים מותאמים** ב-`functions.php`, למשל `/{עיר}/expert/{slug}/` (עם משתנה `mc_city`) ו-`/{עיר}/{slug}/` לכתבה.
2. **Main query:** וורדפרס מריץ שאילתה אוטומטית לפי הפרמטרים (`WP_Query`).
3. **Template hierarchy:** וורדפרס בוחר תבנית לפי סוג הדף: עמוד בית, פוסט בודד, ארכיון קטגוריה, עמוד מחבר, ועוד.
4. **The Loop:** התבנית עוברת על תוצאות השאילתה ומדפיסה כל אחת. המקביל: `results.map(item => <Card />)`.

**אצלנו שלב 3 מוחלף:** Elementor Pro Theme Builder מחליט איזו תבנית מוצגת לפי **תנאי תצוגה**. בנוסף, `functions.php` בוחר **תבנית לפי עיר** באמצעות מזהי התבניות הקבועים בקוד (למשל כותרת חיפה = 152).

**דבר שכדאי לדעת:** אחרי שינוי של חוקי כתובות, צריך **לשמור מחדש את הגדרות הקישורים הקבועים** (Settings, Permalinks, Save). בלי זה הכתובת החדשה מחזירה 404. זו אחת הבעיות הנפוצות ביותר.

## שלב 5. WP_Query: שפת השאילתות

`WP_Query` הוא ה-ORM של וורדפרס. מקבל מערך פרמטרים ומחזיר פוסטים.

השאילתה של דף העיר, "5 הכתבות האחרונות של חיפה":

```php
$q = new WP_Query([
  'post_type'      => 'post',
  'post_status'    => 'publish',
  'posts_per_page' => 5,
  'orderby'        => 'date',
  'order'          => 'DESC',
  'tax_query'      => [[ 'taxonomy' => 'category', 'field' => 'slug', 'terms' => 'haifa' ]],
]);
```

**באותו עולם שלך, זה מקביל ל:**

```ts
db.articles.find({
  status: 'published',
  categories: { $in: ['haifa'] },
}).sort({ date: -1 }).limit(5);
```

**מה קורה בפועל ב-SQL:** `wp_posts` עושה JOIN ל-`wp_term_relationships` (בשביל העיר). עם כמה מאות מומחים וכתבות זה מהיר. עם מאות אלפי כתבות (ההיסטוריה של האתר הישן) צריך לשים לב לשאילתות עם הרבה `meta_query`.

**אצלנו השאילתות הן פילטרים ב-hook.** ב-Elementor נותנים ל-Loop Grid "Query ID", והקוד משנה את השאילתה:

```php
add_action('elementor/query/mc_site_posts', function($q){
  // כתבות העיר, או כתבות כחולות נבחרות
});
```

השאילתות הקיימות: `universal_city_loop` (בלוק שמחזיק נושא בעיר הנוכחית), `mc_site_posts`, `mc_networking` (כתבה אחרונה לכל מומחה).

## שלב 6. Hooks, תוספים ועיצוב (theme)

**Hooks** הם מערכת האירועים של וורדפרס, ובעזרתם מרחיבים אותו בלי לשנות את הליבה.
- **Action:** "משהו קרה, תריצו קוד" (כמו event listener). דוגמה: כתבה נשמרה.
- **Filter:** "קחו ערך, שנו אותו והחזירו" (כמו middleware או reducer). דוגמה: שנו את ה-canonical של דף.

**Plugin:** חבילת PHP שנטענת בכל בקשה ומשתמשת ב-hooks. **Theme:** שכבת התבניות. אצלנו Hello Elementor Child, ו-Elementor Pro מחליף את רוב העבודה של ה-theme.

**הקוד המותאם שכבר קיים:**
| קובץ | מה עושה |
|---|---|
| `functions.php` (ערכת הילד, 1,741 שורות) | שורטקודים של רשימות מומחים, `author_category`, חוקי כתובות, בחירת תבניות לפי עיר, הסתרת מומחה לא פעיל, שאילתות Loop |
| `mcity-tools` (תוסף) | תיבת שיוך עיר ונושא בעורך כתבה (`mct_forward`, `mct_reverse`), מסנני רשימת כתבות |
| `mcity-expert-answers` (תוסף) | שאלה למומחה, קישור במייל עם טוקן, עמוד תשובה |

**`mu-plugin`:** תוסף שנטען תמיד ולא ניתן לכיבוי ממסך הניהול. מתאים ללוגיקה של הפרויקט.

**השוואה זהירה:** תוסף הוא לא npm package מבודד. כל התוספים חיים באותו תהליך, יכולים להתנגש, ואין sandbox.

## שלב 7. Elementor

**Elementor** הוא בונה עמודים חזותי. **המעצב בונה בו את ה-UI.**

דברים שחשוב להכיר:
- **פריסת העמוד נשמרת כ-JSON** בשדה `_elementor_data` ב-`wp_postmeta`. עץ של widgets.
- **Theme Builder (Elementor Pro):** מאפשר לבנות תבנית של Header, Footer, פוסט בודד, וארכיון, ולהחיל אותה לפי **תנאי תצוגה**. אצלנו יש כותרות ותחתיות לכל עיר.
- **Loop Grid + Loop Item:** מעצבים כרטיס אחד (Loop Item), וה-Loop Grid מריץ שאילתה ומציג אותו לכל תוצאה. המקביל: `results.map(<Card />)`.
- **Query ID:** שם שנותנים ל-Loop Grid, שמאפשר לקוד שלנו לשנות את השאילתה שלו.
- **Dynamic Tags:** "חורים" בתבנית שמתמלאים בערך משדה. המקביל: `{item.title}` ב-JSX.
- **Forms:** טפסים. "Collect Submissions" שומר את הפניות במסד (⚠️ לא אומת שמופעל).

## שלב 8. ACF: איפה הוא נכנס

ACF (Advanced Custom Fields) הוא תוסף שנותן **ממשק להגדיר שדות מותאמים, ולחבר אותם ל-Elementor.** הוא לא מחליף את Elementor ולא את ליבת וורדפרס. אצלנו זו **הגרסה החינמית** (6.8.11).

**מקבילה:** כלי מסוג Strapi (בונה שדות בממשק) בלי שכבת שאילתות. השאילתות נבנות ב-Elementor ובקוד.

| יכולת | בחינמי? | הערה |
|---|---|---|
| שדות בסיס: text, textarea, number, email, url, image, select, true_false, date_picker, oembed | כן | |
| `relationship`, `taxonomy`, `user`, `post_object` | כן | קשרים ושיוך |
| `tab`, `group` | כן | ארגון במסך העריכה |
| **Repeater, Flexible Content, Gallery, Options Pages** | **לא** (Pro) | לכן קישורים מרובים הם זוגות שדות קבועים |
| רישום CPT וטקסונומיות בממשק | כן (ACF UI) | כך נרשמו `videos`, `section`, `cat-2`, `video_place` |

**איפה שדות חלים:** על פוסט, עמוד, **משתמש** (כך מוגדרים שדות מומחה), מונח ועוד. קריאה: `get_field('profession', 'user_' . $id)` למשתמש, ו-`get_field('lead')` לפוסט.

**שדה `taxonomy` עם `save_terms`:** שומר את הבחירה גם כקשר בטבלת `term_relationships`. על משתמש זה כותב את מזהה המשתמש בטבלה המשותפת (ראה שלב 1).

**ייצוא וסנכרון:** קבוצות שדות מיוצאות כקובץ JSON, ואפשר לייבא לעותק אחר. ⚠️ לא אומת אם האתר משתמש ב-Local JSON.

**כללי אצבע שלנו:**
- שדות חדשים תמיד בקבוצה נפרדת, לא בקבוצות שהמעצב חיבר.
- לא משנים שם שדה קיים. הערכים הישנים נשארים בשם הישן.

## שלב 9. איך הכל מתחבר: הולכים על `/haifa/`

הדוגמה המלאה לדף עיר, מקצה לקצה:

1. **הדפדפן** מבקש `/haifa/`.
2. **SiteGround Optimizer** בודק אם יש HTML שמור. אם כן, מחזיר אותו וזהו.
3. אם לא, **PHP** נטען. `haifa` היא קטגוריה (מזהה 5), ולכן הכתובת מזוהה כארכיון קטגוריה.
4. **Elementor Theme Builder** מוצא תבנית ארכיון, ו-`functions.php` מחליף כותרת ותחתית לפי מזהה העיר.
5. בתבנית יש כמה **Loop Grid**, אחד לכל קטע (חדשות, צרכנות, מומחים...). לכל אחד **Query ID**, והקוד משנה את השאילתה לפי העיר הנוכחית.
6. כל תוצאה מרונדרת דרך **Loop Item** (הכרטיס), עם **Dynamic Tags** שמחוברים לשדות (`title`, `lead`, תמונה).
7. **HTML מוכן** חוזר לדפדפן, ו-SiteGround שומר אותו.

**מי אחראי על מה:**

| שלב | אחראי |
|---|---|
| קבוצות שדות חדשות (שלב 8) | **אנחנו** (בעותק שלנו) |
| קוד בתוסף משלנו (שלב 6) | **אנחנו** |
| חיפוש גלובלי והגירה | **אנחנו** |
| תבניות, Loop Item, שאילתות ב-Elementor, עיצוב | **המעצב** |
| החוזה בין השכבות | **שמות השדות בחוזה הנתונים** |

## שלב 10. מתי כותבים קוד ומתי מגדירים

**ברירת מחדל: להגדיר בממשק, לא לכתוב קוד.** ACF ו-Elementor אמורים לכסות את רוב הצרכים.

**מה כנראה ידרוש קוד (תוסף משלנו, למשל `mcity-core`):**

| צורך | למה |
|---|---|

## שלב 11. PHP ל-TypeScript developer, בחמש דקות

| TS | PHP |
|---|---|
| `const x = 1` | `$x = 1;` |
| `{ a: 1 }` (אובייקט) | `['a' => 1]` (מערך אסוציאטיבי) |

**ההבדל הגדול:** ב-PHP שורה קוראת לשורה, בלי async. כל בקשה רצה מההתחלה ונגמרת. אין מצב משותף בין בקשות, חוץ ממסד הנתונים והמטמון.

## שלב 13. מלכודות נפוצות

1. **שם שדה הוא מחרוזת.** שינוי שם לא נכשל בקומפילציה, הוא פשוט שובר תבנית בשקט. ואין migration אוטומטי: הערכים הישנים נשארים בשם הישן ב-`wp_postmeta`.
2. **כל ערך ב-`postmeta` הוא מחרוזת.** מערכים נשמרים בצורה מסודרת (serialized). **`mcity_cities` נשמר כמערך של מזהים כמחרוזות, והשאילתות משתמשות ב-LIKE** על `"12"`. מספרים במקום מחרוזות לא יימצאו.
3. **מטמון בכל מקום:** page cache, מטמון CSS של Elementor, מטמון אובייקטים. "שיניתי ולא רואים" הוא כמעט תמיד מטמון.
4. **WP-Cron:** כתבות מתוזמנות (`future`) מתפרסמות על ידי cron שמופעל כשיש ביקור באתר. בפרודקשן מקובל להחליף ב-cron אמיתי של השרת.
5. **שמירת permalinks:** אחרי שינוי rewrite חייבים לשמור מחדש, אחרת 404.
6. **סלאגים בעברית:** כתבות עם סלאג עברי מופיעות בכתובת מקודד (`%d7%...`). הערים באנגלית (`haifa`). צריך להחליט על מדיניות. **ועוד: slug של כתבה ששווה ל-slug של עיר מתנגש** (קרה: `rehovot`).
7. **תוספים מתנגשים ומתעדכנים.** לנעול גרסאות, ולבדוק לפני עדכון.
8. **אבטחה:** כל קלט חייב לעבור סניטציה (`sanitize_text_field`) והדפסה בטוחה (`esc_html`). שאילתות SQL ידניות עם `$wpdb->prepare`. **קוד שמריץ PHP מרחוק (כמו Novamira) לא נשאר בפרודקשן.**
9. **הרשאות:** לא ליצור משתמשי אדמין לכולם. Contributor לכתבים, Editor לעורכים.
10. **מומחה לא פעיל נעלם:** אם `mc_active='0'` או `mc_subscription_end` עבר, הכתבות והדף שלו מוסתרים. בהגירה זה חייב להיות נכון.
11. **מזהים מקודדים בקוד:** ערים 5 עד 18, מזהי תבניות, מחברים 1 ו-6, המשתמש `portvbaq_admin`. הוספת עיר דורשת קוד.
12. **תוצאות חיפוש וארכיונים חושפים הכל:** ברירת מחדל, וורדפרס מאנדקס ומציג פריטים שלא תכננת להציג. לבדוק מה ציבורי.

## שלב 14. תרגיל ליום הראשון

מטרה: לעבור את כל המסלול בקטן, **על העותק שלנו ובקריאה בלבד** (לא נוגעים באתר של המעצב).

1. **פתח כתבה קיימת בעורך** וראה את תיבת "מאפייני פוסט" (`mcity-tools`). שים לב אילו קטגוריות נכתבות כשמסמנים עיר ונושא.
2. **פתח `Posts → Categories`** וראה את מבנה העיר: מונח אב ו-9 ילדים בשם `{עיר}-{נושא}`.
3. **ב-ACF** פתח קבוצת שדות של מומחה וראה אילו שדות יש, איפה הם מוגדרים, וסוג כל אחד.
4. **פתח מומחה** (`Users → מומחים`) וראה את העמודות: סיום מנוי, צפיות, תחום.
5. **פתח `/wp-json/wp/v2/posts?per_page=3`** וראה את הנתונים כ-JSON.
6. **ב-Elementor ← Theme Builder** ראה אילו תבניות קיימות ואיזה תנאי תצוגה לכל אחת.
7. **שמור permalinks** ובדוק ש-`/haifa/` נטען.
8. **קרא את `functions.php`** ואתר את `mc_expert_city()` ואת חוקי ה-rewrite.

אחרי התרגיל תבין את כל הצנרת, ותוכל לקרוא את החוזה כמו מי שבנה אותו.
