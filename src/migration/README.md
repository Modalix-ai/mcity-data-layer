# חבילת המרה מהדאמפ הישן (MCity)

קוראת את הדאמפ של האתר הישן (SQLite, קריאה בלבד) וכותבת **קבצי ביניים** (JSONL) ודוח. **לא נוגעת באתר ולא כותבת לוורדפרס.** טוען WP-CLI (שיכתוב את הביניים לאתר) ועיבוד תמונות עוד לא נכתבו.

## הרצה

```bash
python -m mcimport run --db /path/old.db --out /path/OUTSIDE_REPO/out --as-of 20261122
```

| פרמטר | משמעות |
|---|---|
| `--db` | הדאמפ כ-SQLite (נפתח בקריאה בלבד) |
| `--out` | תיקיית פלט. **חייבת להיות מחוץ לריפו** (מידע אישי); הכלי מסרב אחרת |
| `--as-of` | תאריך לחישוב פקיעת מנוי (YYYYMMDD). ברירת מחדל: היום |
| `--limit N` | רק N כתבות ראשונות (לבדיקה) |
| `--policy k=v` | מדיניות (חוזר). ראו למטה |
| `--only` | `users,articles,forum` (כרגע משפיע רק על מה שנכתב) |

דורש Python 3.9+ בלבד (ספרייה סטנדרטית).

## פלט

| קובץ | תוכן |
|---|---|
| `users.jsonl` | מומחים (`expert:ID`), חשבונות צוות (`staff:*`) וכותבים (`writer:ID`) |
| `articles.jsonl` | כתבות עם עיר, נושאים, כותב, תאריכים ב-GMT, slug, `hold`, `flags` |
| `forum.jsonl` | שאלה עם תשובות מקוננות ו-`bucket` |
| `sections.jsonl` | סיווג כל מדור ישן, ורמז התאמת שם למומחה למדורים שלא סווגו |
| `report.md` | דוח קריא: מה הועבר, מה ממתין, ולמה |
| `manifest.json` | גרסה, מדיניות, ו-sha256 לכל קובץ (הרצה חוזרת נותנת אותם ערכים) |

## hold ו-flags

- **`hold`**: החלטה פתוחה. רשומה עם hold לא נכתבת לאתר. כך שום דבר שתלוי בלקוח או במעצב לא נכתב בשקט.
- **`flags`**: לידיעה בלבד (לא עוצרים).

## מדיניות (`--policy k=v`)

ברירות המחדל הן **תשובות הלקוח מ-24.11.2026**. הערכים: `exclude` (מוסר, לא נכתב ולא ממתין), `hold` (ממתין להכרעה), `include`.

| פרמטר | ברירת מחדל | הערה |
|---|---|---|
| `cutoff_year` | `2015` | כתבות מלפני השנה מוסרות (2015 נכללת) |
| `pre_cutoff` | `exclude` | `hold` מחזיק במקום להסיר |
| `marketing_agency` | `exclude` | תוכן שיווקי **בלי קרדיט** ("תוכן שיווקי" בלי שם, וכותבים שלא ברשימת הסוכנויות שנשארות): 124 כתבות |
| `marketing_agency_kept` | `include` | 6 סוכנויות קידום קישורים שהלקוח אישר להשאיר (buypost, Best Links, אופיר כתבות תדמית, Mega Links, לינקשייק, Seo Rush): 5,421 כתבות, חתומות על חשבון הצוות "תוכן שיווקי" |
| `circles` | `include` | מעגלי נטוורקינג (24 רשומות במיפוי): נשארים, `kind=circle` בקובץ המשתמשים |
| `removed_sections` | `exclude` | מדורים שהלקוח הסיר והכתבות שלהם (`mappings/removed_sections.csv`, כרגע פלמנקו 239) |
| `removed_records` | `exclude` | חשבונות פנימיים, רשומות בדיקה ו-master: לא נכתבים. הכתבות שלהם נחתמות על הכותב |
| `marketing_expert` | `include` | תוכן שיווקי **עם קרדיט** של מומחה (מקושר) או כותב בשם מומחה/חברה; נחתם על שמם |
| `forum` | `exclude` | שאלות שפורסמו ולא הומרו לכתבה |
| `inactive_experts`, `expired_experts` | `include` | נשארים (הלקוח, מטעמים משפטיים), מוסתרים מהרשימה ולא מהכתבות |
| `realestate_experts` | `hold` | טרם הוכרע |
| `shared_email` | `blank` | `keep_first_active`. הלקוח יחזיר רשימה מתוקנת |
| `section_exclusion` | `hold` | כתבות שכל מדוריהן נדל"ן, בחירות או בדיקה |
| `slug_policy` | `hebrew` | `translit` (ממתין למעצב) |
| `writer_policy` | `contributor` | `staff` |

## איך מסווגים מדורים שלא סווגו

מוסיפים שורה ל-`mappings/section_overrides.csv` (`id,kind,topic,expert_id,note`) ומריצים שוב. הרשימה נמצאת בדוח, וכוללת רמז להתאמת שם למומחה.

## בדיקות

```bash
python -m unittest discover -s tests            # סינתטי, 33 בדיקות
MC_OLD_DB=/path/old.db python -m unittest discover -s tests   # כולל בדיקת ספירות מול הדאמפ האמיתי
```

## בדיקת תיקיית תמונות (לפני כל עיבוד)

```bash
python -m mcimport images-manifest --db old.db --out images_manifest.csv       # רשימת הקבצים הצפויה (שמות בלבד)
python -m mcimport images-check --folder D:\\old_images --manifest images_manifest.csv --report images_report.md --db old.db
```

`--db` (אופציונלי) מוסיף לדוח כמה כתבות איבדו תמונה ראשית, לפי שנה. חשוב כי הלקוח ניקה תמונות באתר הישן אחרי שהדאמפ נלקח, ולכן "חסר" אינו בהכרח שגיאה: הרשימה היא הגבול העליון.

הבדיקה לא קוראת ולא ממירה תמונות, רק סורקת שמות וגדלים (תיקייה של 10GB בשניות). מדווחת: כמה נמצאו וכמה חסרים לפי מקור (ראשית בכתבה, בתוך תוכן, מומחה, פורום), קבצים שאינם תמונה, קבצים כפולים בתת-תיקיות, ואפס בייט. ההמרה (גדלים ופורמט) והעלאה לאתר ממתינות להגדרות המעצב.

## מה לא כאן (בכוונה)

- המרת תמונות והעלאתן (ממתין לפורמטים וגדלים מהמעצב)
- כתיבה לוורדפרס (טוען WP-CLI אידמפוטנטי לפי `_mc_legacy_id`, עם `update_field`)
- התאמת מדור ישן ל-term בטקסונומיה `section` (נעשית בטוען)
- סיסמאות ושליחת מיילים: אין. הטוען ייצור סיסמה אקראית ויכבה מיילי ברכה
- `data.city` של מומחה הוא מזהה מספרי; ממתין לטבלת הערים מ-SPD (נשמר ב-`address_fallback_city_id`)


## סיווג ידני של רשומות מומחה

`mappings/expert_records.csv` מסווג רשומות מומחה לפי מזהה: `circle` (נשאר), `internal`, `test`, `entity_removed` (מוסרים). רשומה בתחומי 92/99/100 שלא במיפוי נשארת מוחזקת (`not_an_expert`) עד החלטה. כל שינוי בהחלטת הלקוח הוא שורה בקובץ הזה, בלי שינוי קוד.

## מדורים שהוסרו

`mappings/removed_sections.csv` (id, name, note) מפרט מדורים שהלקוח הורה להסיר. כל כתבה ששויכה למדור כזה מוסרת כולה, גם אם שויכה גם למדור אחר (`excluded_removed_section` בדוח). המדור מסומן `removed` ב-`sections.jsonl`. מדיניות: `removed_sections=exclude|include`. כרגע רק 239 (פלמנקו, 71 כתבות). רשומה 619 ("ארגונים וקבוצות") והמיניסייט שלה נשארים.

## תת-אזורי חדשות

כתבה במדור תת-אזור (`SUBAREA_REGION` ב-`mcimport/sections.py`) מקבלת את האזור של המדור, ולא את הדומיינים שסומנו בכתבה. כרמיאל והגליל העליון ← ערי הצפון (הלקוח, 24.11). המדורים 361 ו-539 לא ברשימה ונשארים לפי דומיינים של הכתבה.

## אילוץ לטוען: בלי `pending`

היבוא מוציא `status` של `publish` או `draft` בלבד (בישן רק `active` 0/1). אסור לטעון כתבה כ-`pending`: תהליך אישור הכתבות של המעצב (החלטה 92) שולח מייל למנהל האתר על כל מעבר ל-`pending`. בנוסף, שאילתות חיפוש ורשימות צריכות `post_status='publish'`.
